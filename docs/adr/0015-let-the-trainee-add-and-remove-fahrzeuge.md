# Let the Trainee add and remove Fahrzeuge

The Roster is no longer fixed at two Fahrzeuge. The Trainee can add Fahrzeuge and remove those not in use, so they can train with the vehicles their own Wache sends. This partly supersedes [Decide the contents of the fixed Tally roster](0006-decide-the-contents-of-the-fixed-tally-roster.md) (8 Tallys) and the `1`–`8` shortcuts in [Design how the Trainee handles Tallys and the clock](0005-design-how-the-trainee-handles-tallys-and-the-clock.md).

1. **One to four Fahrzeuge**, each with the four Tallys AT-F, AT-M, WT-F and WT-M. Three Fahrzeuge already fill the Checkbox's six Trupps (parameter [72]); four was chosen because a real Einsatz can have that many.
2. **In use** means that a Tally of the Fahrzeug is in a logged-in Trupp or on the open Anmeldefenster. Stored Einsatzprotokolle do not count, because they keep a copy of the LCD name.
3. **Any Fahrzeug not in use can be removed**, not only the last. So each Fahrzeug gets a stable identity when it is added, and its Tally ids derive from that identity, not from its position. Removing one Fahrzeug never renames another Fahrzeug's Tallys or breaks a running session. We rejected removing only the last Fahrzeug, which would have kept positional ids: the Trainee could then not remove the HLF while the LF is on an Einsatz.
4. **Shortcuts follow the current position**, not the identity: `1`–`8` for the Fahrzeuge in positions 1–2, and Shift + `1`–`8` for positions 3–4, matched on the physical key (`Digit1`…) because Shift changes the character on German layouts. We rejected a two-key chord (Fahrzeug, then role) because it breaks the existing `1`–`8`.
5. **Adding and removing happen in the names form**, in both the first-launch dialog and Einstellungen. "Fahrzeug hinzufügen" is disabled at four Fahrzeuge. "Fahrzeug entfernen" is disabled on the last Fahrzeug and on one in use, with a note saying why. Nothing applies before Speichern, and Abbrechen undoes everything, so there is no separate confirmation. New Fahrzeuge are appended at the end, and Fahrzeuge cannot be reordered.
6. **A new Fahrzeug is prefilled** with the first of `HLF 1/43`, `LF 1/45`, `DLK 1/33`, `TLF 1/23` whose Kurzname is not yet taken, so adding one is a single click. The factory state stays at the first two.
7. **Kurznamen are unique** in the Roster, compared trimmed and ignoring case, because two Fahrzeuge with the same Kurzname would show identical names on the LCD. The device does not enforce this. Funkrufnamen may repeat.
8. **The stored device memory changes shape**, so per [Decide what survives a page reload](0007-decide-what-survives-a-page-reload.md) older data and the running session are wiped, never migrated.
